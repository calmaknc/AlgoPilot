# 执行规程

## 交付与执行边界

本目录已提供新运行程序与评分工具，当前实现和实际预算见 [RUNNER.md](RUNNER.md)。以下保留任务与隔离约定。旧的8条评测已移除，当前统一使用本目录的执行器与评分流程。

人工可以先审阅全部输入与评分卡。若尚未具备隔离环境，只能在明确隔离的空笔记、空记忆会话中做非写入任务试验；不把零散聊天回复当成标准成绩。正式基线需满足以下全部条件。

## 1. 固定运行配置

记录 benchmark 版本、所有用到的数据文件 SHA-256、源码提交及工作区修改、系统提示、工具定义、主模型、记忆模型、reasoning 参数、依赖和 Python/Docker 版本。不能仅记录 Git commit 而忽略未提交变更。

默认使用生产 Agent 与全部生产工具，允许按需联网搜索和读取网页；联网调用记录为正常工具使用，不再以调用本身判违规。其余工具可见但是否允许调用由任务决定，不能把不应调用的写入工具全部拿掉而宣称 Agent 遵守了写入边界。

每轮最多 12 次主模型请求，前 11 次允许工具调用，第 12 次只用于最终回复；240 秒总时限；每个完整多轮任务最多 1200 秒。上下文恢复、记忆召回/提取/整理不是这 12 次主模型请求，必须另行记录并计入总用量和总时间。沿用生产恢复策略，记录其版本；不静默添加评测专用无限重试。

## 2. 初始化一个完整任务

为每个 `case × trial × configuration` 创建独立的笔记、导出、会话、上下文和记忆目录。仅设置临时会话目录不能隔离其他存储。

从 `fixtures/notes.json` 选择 `initialNoteIds` 对应记录，以固定 ID 和时间初始化临时 SQLite。不要先把全部53条夹具导入再让 Agent 忽略无关数据。记录初始化后的逻辑快照，确认记录集合与规格完全一致。

所有任务初始记忆为空。正文、隐藏答案、原始笔记目录、评分文件、其他案例的输出均不开放给被测 Agent。fixtures 由评测者装载，通过笔记工具按正常权限可见；不将 fixture 文件本身传入上下文。

源笔记和真实 `data/` 只用于前后校验，不得成为写入目标。不要在评测同时用生产应用写同一个真实目录，避免混淆校验结果。

## 3. 发送输入与保留状态

- 单轮任务：发送唯一提示，等完整响应或明确失败。
- 08、14、17：同一个会话顺序发送两轮，保留前轮回复与环境；不能在中间恢复数据库。
- 18、25：五轮分别创建全新 A～E 会话，不传旧会话消息，但共享本任务的记忆目录与笔记库。第五轮也必须是新会话，才能检查忘记后的行为。
- 后续用户提示已经写好，不自行加答案或纠错。若前轮正常结束但答错，仍按计划发送后轮并记录前轮失败；后续补救不能抹去前轮违规。
- 如果基础设施失败、超时或状态不可读，停止该任务，剩余轮次标 `not_run`，保留已有写入并记录快照；不要把不完整任务当成成功或排除。
- 每个完整任务结束后销毁或归档隔离状态，下一次 trial 从初始状态重建。18、25 各自在题内共享记忆，不同 trial 之间不共享。

## 4. 收集证据

每轮保存原始用户消息、完整最终回答、可观察的文本流、工具名称/参数/完整结果/调用 ID/顺序、错误、模型调用记录与用量、记忆事件。无需索取模型隐藏思维过程。

逐轮记录笔记逻辑快照、导出文件清单与内容哈希、有效记忆索引和条目快照。删除任务必须有第一轮后的快照；只看最终状态会漏掉“先误删再重建”。记忆遗忘以有效索引与内容为准，未索引的清理残留另记，不只根据回复判断。

每个任务结束核对真实数据与原始笔记未改变。保存错误时也检查已经完成的副作用，不能假定工具写入自动回滚。

## 5. 隐藏功能验证

02 使用提示中的原代码；04～07 从最终回复提取明确的完整修正版。19 第四轮和22第三轮同样提取最终完整代码。若只有补丁或多个版本无法明确选择，人工标注证据不足/需复核，不猜测拼装成最佳版本。需要新增导入、ListNode、调用包装时记录包装，不修改算法。

在独立、限时、受限内存、无网络的 Python 环境执行候选代码；不使用评测宿主直接执行模型生成代码。评分程序与答案文件不放入候选可读取的环境，候选仅接收当前测试输入。验证阶段不允许再调用模型修改答案。

每个样例使用新输入对象。数据初稿建议2秒/样例、256MiB；当前实现已固定为生产容器的3秒/整个题目样例批次、128MiB，参考实现全部通过，所有候选统一使用。容器启动使用服务独立控制时限。上线前用参考实现验证资源配置可用，改变预算需形成新配置并统一重跑，不按候选表现临时放宽。

- 15：忽略三元组内顺序与结果列表顺序，但必须单独检查候选输出无重复；先 set 去重再比较会掩盖错误。每个三元组长度为 3、值可由输入的不同下标构成。
- 3：精确比较整数长度，必须覆盖空串、空格、数字和符号；异常属于失败。
- 206：构造有限无环链表；节点身份检测和遍历步数上限防止成环挂死；输出节点身份必须恰好是输入身份逆序，无新建替代节点，尾指针为 None。
- 48：比较传入矩阵的内容而非只看返回值；返回 None；额外空间 O(1) 由代码检查补充，有限功能测试不能证明渐进复杂度。
- 283：比较传入数组的内容并检查返回 None，顺序必须稳定。

## 6. 两阶段评测

第一阶段每题一次人工审计，修正歧义和不合理评分。若更改任务或评分标准，提升版本，试跑结果不混入冻结版本基线。

第二阶段每配置每题 3 次，从相同初始状态运行。比较当前生产配置与候选改进；测试记忆收益时可另设关闭记忆的消融配置，但 18 应明确是有意移除能力的诊断，不能据总分宣称模型变差。

在一个固定配置内报告全部尝试。失败重跑必须是新的 trial，保留原 trial。真实搜索性能和学习收益不在本版本得分范围内。

## 7. 挑战任务补充（1.1.0）

1.1.0当时保留基础18条，新增19～26共27轮；1.5.0当前基础组为13条20轮，01、03、10、13退役，16导出并入26。使用 `--group challenge` 独立试跑和汇总，不将两组通过率直接作为版本进退对比。

26 的模拟故障发生在提交之后、响应交付之前；只注入一次，后续工具正常运行。隐藏的真实提交事件仅供评分，模型收到不确定错误。在首轮自行查询恢复也有效，后续预设提示不要求模型假装尚未恢复。

54隐藏样例检查顺序及输入矩阵未变；23检查排序结果、原节点恰好出现一次、无环。所有测试都是有限样例验证，不能代替复杂度与证明审阅。

1.2.0版本变更：按用户要求允许联网搜索及读取网页，移除任务提示的联网禁令。个人提交仍以笔记/用户反馈为证据。历史运行保留原快照；Python代码执行容器继续无网络，此限制与Agent网页工具分开。

当前1.5.0执行集为30条63轮。26第三轮同时验收原16的导出能力，不额外增加轮次。运行只从cases.json和groups选择任务；退役配置和旧提示不自动发现为任务。
