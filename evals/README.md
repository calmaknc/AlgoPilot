## 文件怎么使用

- [CHALLENGE-DESIGN.md](CHALLENGE-DESIGN.md)：同一benchmark中19～26的设计与来源说明；实际输入、状态和检查项以cases.json为准。
- [cases.json](cases.json)：当前30条启用任务的评测规格（编号有空缺），含轮次、会话、初始状态、检查项和证据要求。不要整体发给 Agent。
- `prompts/`：唯一允许作为对应轮用户输入的文件；每次只发送当前轮。
- [fixtures/notes.json](fixtures/notes.json)：53 条可用于初始化的笔记；每个案例只装入其 `initialNoteIds` 指定的记录。
- [评分规程](SCORING.md)：判定、失败归因与成绩统计。
- [执行规程](PROTOCOL.md)：状态隔离、逐轮运行、证据和预算。
- [参考核验记录](REFERENCE_CHECKS.md)：测试答案已验证到什么程度；不等于 Agent 通过。
- `grading/rubrics/`：30份启用评分卡；另保留5份退役评分卡用于历史审计，以 `cases.json` 选择当前任务。
- `grading/hidden-tests/`：9 组、共 493 个评分者隐藏输入与期望结果。
- `grading/sources/` 与 [sources.json](grading/sources.json)：32 篇源笔记原样快照、文件和代码哈希、定位行号。仅供评分审计。
- `grading/expected-content/`：保存、追加任务的逐字符期望正文。
- [成绩空表](grading/results-template.json)：未评分的结构化记录模板。

## 初始数据和信息边界

标准 fixture 正文与源笔记逐字相同；ID、标签、标题字段和时间是评测元数据（检索组按原笔记日期排序，其余初始记录采用固定时间），不是原始练习日期。正文仍保留原始日期。`h100-3-draft` 是显式标注的评测草稿，用于制造可解释的删除歧义，不能当成真实历史。18 的学习偏好是受控场景，不宣称是本人真实偏好。

当前算法任务02、04～09的笔记库为空，不开放源目录、评分目录、完整 fixtures 或完整历史总结，避免拿到修正版。检索和笔记任务允许通过真实工具读取为该任务装入的笔记，这属于合法任务证据。

本版本全为**开发/回归集**，没有假称独立保留集。同题素材被多次使用，30个任务并非30道独立算法题。将来建立保留集时，应使用未参与本轮设计的新题/新事件，并让所有同源变体和跨题依赖留在同一分区。
