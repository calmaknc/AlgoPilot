# 来自真实刷题笔记的 Agent 评测用例

日期：2026-10-23。共 8 条用例，来自 3886、1569、49、3644 四篇真实学习记录。代码摘录保留原样，用户提示按评测目标重新组织，并非历史聊天的逐字转录。没有修改源笔记，也没有导入应用的真实笔记库。

这是一组评测规格与测试数据，现提供真实模型执行器 `run-live.mjs`。逐次运行证据保存在 `runs/<UTC 时间>/`；人工评分另见运行报告。`validate.mjs` 只校验用例文件和笔记数据格式，不能证明 Agent 通过。

## 文件与输入隔离

- `prompts/*.md`：每条用例唯一的用户消息，可直接复制到新会话。
- `cases.json`：评分者使用的来源、规则、禁止行为、期望值。**不要把整份文件发给被测 Agent**，特别是联网题的标题、slug 和预期答案。
- `fixtures.json`：符合当前 `PracticeNote` 格式的三条初始笔记。思路和总结是基于原笔记整理的测试数据，代码取自原始代码块；时间是固定的测试时间，不代表原始练习日期。没有给 3644 填入助手参考代码冒充用户代码。
- `validate.mjs`：离线检查 ID、输入文件、工具名称和初始笔记的有效性。
- `REFERENCE_CHECKS.md`：此次独立核对参考答案的范围，不是 Agent 的成绩。

每条来源都记录相对路径、章节、生成时行号和整个源文件的 SHA-256；原始目录可通过 `EVAL_SOURCE_ROOT` 指定（可选，仅用于运行前后的哈希核对）。运行评测不需要把源目录开放给 Agent。调试用例只提供当时原始代码，没有把笔记里的修正答案一并输入。

## 怎样运行第一轮

先在当前应用的新会话里分别粘贴 01、02、03、07、08 的提示。这五条不要求写入笔记；执行会产生正常会话记录。真实模型、搜索和读取可能产生费用，01 需要可用的 Python Docker 环境。

04、05、06 应在隔离环境运行。每次试验重置初始笔记和会话：

1. 04 使用空库；05、06 使用 `fixtures.json` 中的全部三条记录，文件名为 `note_<id>.json`。
2. 保存执行前快照，运行提示，收集工具名称、参数、完整结果、最终回复、耗时和 Token。
3. 检查执行后的笔记状态，并与 `cases.json` 中对应规则比较。
4. 重复试验前恢复初始状态，避免上次保存或标签更新影响本次结果。

**仅给 `createAgentService` 传临时会话目录，仍不能隔离笔记工具。** `run-live.mjs` 另外通过 `createAgentTools` 向全部六种笔记工具注入临时笔记/导出目录，并为上下文与记忆设置独立临时目录，再通过 `requestModel` 的第六个参数注入独立注册表。执行器不会把 fixtures 导入真实笔记库；每条用例使用独立初始状态，真实模型只能看到该用例提示与工具返回。原始 Markdown 目录仅由执行器读取文件哈希，不交给 Agent。

## 评分方法

每次运行单独记录：

| 字段 | 规则 |
| --- | --- |
| 任务完成 | 对应 `checks` 全部满足，且没有触发 `forbidden`，才记为通过 |
| 约束遵守 | 单独记录是否泄露完整解法、编造验证结果、擅自修改原文等 |
| 失败分类 | 模型选错工具、推理错误、约束违反、存储错误、外部服务或容器失败 |
| 成本 | 模型输入/输出 Token、总耗时、联网调用次数；缺失用量记未知 |
| 证据 | 最终回复、完整工具调用与返回、执行后笔记快照；不依赖模型自述成功 |

`requiredTools` 只表达必须出现的工具，不指定固定完整轨迹；但 06 明确要求更新前先读取。网络正文已充分时，07 不强制再读取；08 不强制先搜索。02 的参考反例不是唯一正确答案，其他经核对有效的反例也接受。

对 04 按字符检查 `正文中的原始思路` 和代码块内的 `原始代码`，包括换行和缩进；不得因保存时顺手加了 import 就判为原样保留。06 用深度比较检查字段，允许 `updatedAt` 保持相同或变为不早于原值的合法时间，不要求每次时间戳必然不同。

搜索、抓取或容器失败时，Agent 如实说明可以获得“约束遵守”，但任务仍记录为未完成，并保留基础设施失败原因。报告全部尝试的完成率，同时列出外部失败数，不静默排除或只挑成功结果。

先各跑一次人工检查评分规则，之后同一模型配置各跑 3 次，报告每条通过次数（如 2/3），不只保留最好一次。固定代码提交、模型标识、提示词和用例版本。这 8 条只反映这些具体场景，不代表全面能力，更不能证明长期学习效果。

离线格式检查：

```sh
node evals/leetcode-real-notes/validate.mjs
```

真实模型运行（产生 API 费用，调试用例需要 Docker）：

```sh
node --env-file=.env evals/leetcode-real-notes/run-live.mjs
```

使用当前 `.env` 的模型与密钥，沿用生产提示词、5 轮模型调用上限和 high reasoning，每条用例设 240 秒总时限，不自动重跑失败任务。脚本保存逐条 JSON、流式 trace、完整工具参数与结果、笔记前后快照、版本和用量；结束后核对真实 data/ 与源笔记目录的哈希。临时数据路径记录在 manifest，便于复核。

执行器只汇总调用是否结束和必需工具是否出现，不自动判断解释质量；最终通过率必须经过逐条评分。失败轮次的 usage 可能不完整，`observedUsage` 仅表示已经收到的已完成请求用量，不等于完整账单。不要把离线格式校验或工具出现次数当作端到端通过率。

单独运行指定用例：

```sh
node --env-file=.env evals/leetcode-real-notes/run-live.mjs 05-retrieve-status
```
