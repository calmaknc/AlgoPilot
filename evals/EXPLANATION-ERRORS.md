# 已观察到的解释错误：证据、正确说法与影响

这些都是既有真实回复中的问题，不是人为编造的失败。需要区别：程序能正确运行、解释某个概念是否正确、以及是否完成了当次用户任务。功能测试通常只覆盖第一件事。

## 1. 把等价递推说成错误写法

证据：`runs/2026-11-11T12-24-55.882Z/18-memory-learning-preference-turn-3.json`。

回复称 `cur=max(0,cur)+x` 不能替代 `cur=max(x,cur+x)`，因为前者“允许空子数组”。这是明确的数学错误：

```
max(x, cur + x) = x + max(0, cur)
```

cur≥0时两边都是cur+x；cur<0时两边都是x。右侧虽然允许丢弃负贡献的旧前缀，但随后一定加入当前元素x，所以当前候选仍非空。

真正容易混淆的是 `cur=max(0,cur+x)`：这个式子在加上x之后还可以整体取0，才可能把空段引入答案。再把best初始化为0，就会对全负数组错误返回0。例如[-3,-1,-2]应返回-1。

为什么重要：这不只是术语，错误解释会让用户否定一个完全正确且常用的等价转移。该次最终代码是对的，不能因此说代码失败；但用户明确问全负为什么正确，解释条目必须记录问题。

## 2. 将“下一步不会变好”误当成“移动高侧不会漏最优解”

证据：同一次运行第18条第五轮。回复步骤写“移动较短侧”，却在理由里说“移动长板一定不会丢失更优解”，前后矛盾。

反例height=[1,4,4]：初始面积2；若总移动较高的右侧，下一对面积1，最终最好只有2。真正最优是后两根，面积4。移动高侧恰好提前丢掉了这个答案的一端。

正确证明是：假设左侧较短，先记录当前面积。固定这个短侧、把另一端往里移，宽度更小且高度上限不超过该短侧，面积不可能超过已经记录的当前值。所以可以排除当前短侧作为起点的剩余候选，然后移动短侧，保留寻找更优解的可能。

重点是**排除哪个端点所对应的候选**，不是证明移动后的面积必然增大。移动短侧后面积也可能下降；算法始终保留历史最大值。

## 3. 混淆算法思想与Python实现的空间

证据：25的两次复测第三轮，以及18复测第三轮。

Kadane只需cur和best两个状态，算法可以用O(1)辅助空间。但这些回答的代码用了：

```python
for x in nums[1:]:
    ...
```

Python列表切片会新建列表，长度约n，因此该具体实现的峰值辅助空间是O(n)。这是复制引用，也同样占用线性空间。若改成遍历下标1到n-1，或使用不复制列表的迭代器，就能实现O(1)辅助空间。

所以合理说法是“状态本身为O(1)，此实现因切片额外使用O(n)空间”，或提供真正不切片的实现。按当前评分口径，在记忆任务中这属于质量备注；若用户明确要求O(1)空间或专门询问这份实现的复杂度，则会影响核心任务。

同类问题：20首轮新增 `sidx=[ord(c)-A for c in s]`，却称所有方案O(1)空间；这个列表同样是O(n)。

## 4. 将初始化简化成“只要出现0就错”

证据：基础09，以及25首次修复复测第三轮、18复测第三轮。

`dp=0, ans=-inf`，随后对每个元素执行 `dp=max(dp+x,x); ans=max(ans,dp)` 是正确的。第一步dp必为第一个元素，ans从未把空段0当作答案。不能笼统说“初始化必须用nums[0]，不能用0”。必须看哪个变量为0、何时更新、是否允许空段。

基础09又说“直接return dp，全负时返回0”。对其提供的[-5,-2,-7]，最终dp实际为-7，ans为-2。return dp的问题是返回了“以最后元素结尾”的局部状态，不是凭空返回0。

25首次修复还说“用nums[0]初始化后，重复处理首元素不影响答案”。对[1]，如果再处理一次1，cur会变为2，明显错误。真正代码用nums[1:]没有重复处理，因此仍能通过功能测试。

## 5. 把堆初始化与优先级错误混为一谈

证据：挑战22首轮。

原始结构是按i递增生成 `(i,node)`。当i互不相同时，元组比较首先由i决定，这个递增列表已经满足按i的最小堆性质，不是“没heapify就必然非法”。

真正问题是按链表编号排序，而合并有序链表需要按节点值排序。改用 `(node.val, i, node)` 后，输入的节点值未必有序，才需要heapify或逐个heappush建立正确的堆。平局时用i避免比较ListNode，也与heapify是否调用是不同的问题。

此外O(N log k)是常见简写；若k个槽位允许大量空链表，还应计入扫描槽位的O(k)。更稳妥的上界是O(k+N log(k+1))。有限测试可以确认输出，不会证明复杂度表达完整。

## 6. 没有条件的“更快/写得更少”断言

证据：基础12称交换版移动零“写操作更少”；挑战20从少量微基准得出“已经最优”。

原两遍覆盖法恰好进行n次元素赋值：写非零元素，再补剩余零。简单的无条件交换版对每个非零元素执行两次槽位写入；全非零数组上可达2n次，并不必然更少。若加上避免自交换等条件，情况又会变化，必须说明具体代码和输入分布。

同样，某个基准上list相等比较比维护差异计数更快，只能证明那组实现、输入和运行环境下的观察，不能证明它对所有输入都最优。

## 如何看待这些问题

- 不把简短铺垫、文字长短或未要求的完整性变成失败理由。
- 不把上述错误说成全部都是“模型不会做题”：多次最终程序和实测结果是正确的。
- 也不把解释错误都当无关紧要：等价转移、指针排除证明会直接影响学习；用户明确要求解释时尤其需要核对。
- 后续改进应优先核验推理链与断言：区分算法和实现；对“必须/一定/不能/最优”寻找反例；让测试同时验证解释所声称的等价性或反例，而非只跑最终程序。

本文件是对已有证据的分析，没有修改生产Agent，也没有将解释问题偷偷加入新检索任务的额外硬门槛。
