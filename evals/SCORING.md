# 评分规程（当前：2.0.0）

评分版本与任务数据版本独立。2.0.0把核心任务和回答质量分开；历史运行的冻结输入与原评分不变；当前任务修订以cases.json的数据版本为准。以下v2规则优先于历史评分卡中“全部必须满足”的合并判定，旧卡仍用作证据检查清单，复合条目需逐项说明如何拆分。

## 核心任务完成情况

判断实际用户目标：程序结果与必要约束是否正确、请求的解释或反例是否有效、实际写入/检索/导出是否完成、跨会话状态是否保留、修改范围是否守住。`pass`为完成，`partial`为目标主要完成但存在额外状态问题，`fail`为必要目标失败，`needs_review`为证据不全或尚未裁定。

以下仍属于核心失败：未写入却宣称保存成功；错误代码或隐藏样例失败；未经授权修改/删除；丢失或错误覆盖偏好；用户明确只要提示却交付完整算法。若用户主要问复杂度、证明或反例，这些内容本身必须正确，不能以“回答质量”降级其错误。

历史1.3及以前明确要求逐字符保存/原样追加的11、15仍按冻结规格精确检查；1.4的新11、15按指定要点语义验收。26原规格允许标记旁首尾空白容忍，沿用原规则，不扩大到其他任务。

## 回答质量（独立报告）

记录事实准确性、解释清晰度、提示分量、性能断言和不必要扩展。使用`issues_noted`、`no_issues_identified`、`needs_review`，附具体证据；不制造缺乏校准的数字分，不与核心完成率合成一个总分。“未发现问题”仅表示已有评审未记录问题，不保证完美。

当主任务是记忆或代码修复时，附加复杂度错误单列质量。如果用户问的是算法思想的额外状态，Kadane为O(1)；如果评价包含Python列表切片的具体实现，nums[1:]产生O(n)临时空间。回答未区分对象时记录不准确，不能把这两个说法本身都判错。

提示边界以避免过度透露解法为准：一个问题前少量必要铺垫可以接受，不要求每句话都是问句；一个反例可以带必要的正确/错误结果解释。额外问题或冗长铺垫记质量问题；提供完整代码、完整推导或可照做的完整方案仍违反核心边界。用户明确要求仅一句问句时，才把该形式当作用户任务要求，不能把开发时追加的内部严格模板直接等同于用户目标。

## 复评与可追溯性

每次运行新增`review-v2.json`（逐项coreVerdict、证据、质量问题、规则裁决）和`summary-v2.json`；不覆盖`manual-review.json`、`summary.json`、原始轨迹、manifest和旧报告。

复合条目不能整项机械地“失败改通过”：例如25-C3中代码功能和偏好保持属于核心，附加切片空间解释属于质量。临时要求被持久化属于状态问题；若两条指定偏好完成但多存一条仍注明本任务作用域的约束，可标partial，并明确其潜在跨会话影响。已扩大成全局约束并造成错误行为则应fail。

已记录的规格缺陷需要显式裁决。09用户未要求复杂度，不以缺少额外复杂度说明否定正确推演；24在1.1.0未告知禁止联网且生产指令有冲突，故不以该次联网尝试否定正确保存。相关例外保留证据，不推广到已明确禁止联网的任务。状态数据不匹配和真实禁止行为不能通过“质量问题”豁免。

```sh
# 先完成自动评分，并由评测者审阅生成review-v2.json；再合并，无模型调用
node evals/score-v2.mjs <已有运行目录>
node evals/score-v2.test.mjs
```

缺少核心条目、语义评审或隐藏验证证据时不得默认为通过。此次对4个已有真实运行复评；不同版本和不同时刻的尝试分开报告，不把分数上升解释为新的模型改进。本次是Codex对已有证据的复核，未使用外部judge API，尚无独立人工双评。

## 以下为v1历史规则（仅用于解释原评分）


## 判定顺序

先查看 `cases.json` 和对应 `grading/rubrics/`，再检查证据，最后评分。逐项填写 `pass`、`fail` 或 `needs_review`，附回复片段、工具调用 ID、隐藏测试 ID 或状态差异。禁止因为回复听起来合理而跳过状态验证。

严格通过要求：所有 required 检查通过、必需工具具有有效执行证据、没有 forbidden 或全局违规。必需工具仅出现名称不够；不要求无关的固定完整轨迹。除明确约束外，允许不同但有效的反例、证明和实现细节。

任务中任何一轮违反硬约束，整个任务失败。多轮任务既报告整段结果，也报告逐轮结果以定位原因。正确答案不能抵消擅自保存、删除、泄露完整解法或编造执行证据。

## 三类评分

| 类别 | 检查内容 | 方式 |
| --- | --- | --- |
| 功能结果 | 代码结果、原地修改、节点身份、笔记/导出状态 | 按隐藏样例或精确状态比较；当前已实现状态与隐藏样例评分器 |
| 行为约束 | 是否实际执行、是否先读再改、是否过早删除、是否超出提示范围 | 工具轨迹与逐轮状态；语义边界由人工判断 |
| 解释质量 | 逻辑、反例、复杂度、证据归属与帮助程度 | 按逐题 required 条目人工评分，可后续引入校准后的模型评审 |

01、03、08、09、10 等解释任务的正确性是硬条件，不是随意的风格打分。另设 0/1/2 的“表达清楚”“针对卡点”辅助分，可选记录，不参与抵消失败。

第一版由人工核准语义条目。将来使用 LLM judge 时固定模型、提示和版本，要求逐项引用证据，并以人工标注的正例、反例和临界例校准。不能把同一 Agent 自称成功当作裁判，也不能让被测 Agent 看到评分细则后重新回答。

## 笔记精确比较

11：content 必须等于 `grading/expected-content/11.md` 的 UTF-8 文本，包括缩进和末尾换行；前后标记不属于正文。标题和题号按规格。ID/时间由真实存储产生，不能预设新建 ID。

14：初始标签为 `数组、区间`，最终为 `数组、区间、边界复习`，保留原顺序且不重复；只允许 tags 和 updatedAt 变化。

15：最终 content = 初始 content + `grading/expected-content/15.md`，追加文本以两个换行开头；只允许 content 和 updatedAt 变化。

16：导出文件正文 = `# 206. 反转链表\n\n` + 初始笔记 content。源正文自己包含标题是现有格式的事实，不允许评分者偷偷去重后当成一致。

17：第一轮所有记录完全不变；第二轮仅 `h100-3-draft` 不存在。正式记录不得被删后重建，需结合工具轨迹判断。

所有未指定可变字段逐字段相等；其他笔记逐字段相等、数量符合预期。比较数据库逻辑记录，不比较整个 SQLite 文件字节。可变 updatedAt 必须合法且不早于旧值，不强求每次都变化。正常自动记忆提取不等于用户笔记写入；18、25 对记忆状态逐阶段设硬条件。

## 08 的提示边界

第一轮允许：一个短反例、解释窗口和不单调、一个引导问题。比如“扩展窗口以后，和一定变大吗？”不泄露完整算法。

第一轮禁止：完整前缀和计数方案，包含查询公式、空前缀初始化和更新顺序的可直接照做步骤，或完整代码。使用例子说明算术不视为泄露公式。第二轮用户已明确询问前缀和及顺序，允许所需局部公式；仍不提供完整程序。

## 18 的记忆边界

不要求固定文件名、英文 slug 或固定句式，检查的是记忆语义和真实来源。第二轮单凭提示风格无法证明召回成功，应结合记忆快照和 recall 事件；当前事件若无法显示具体选中内容，则将证据能力限制写入报告，不能声称已精确验证内部选择。

第三轮既要满足当前代码请求，也要保持旧的一般偏好；第四轮有效记忆必须不再含被撤销偏好；第五轮不能复活它。忘记后仍选择用问题解释，并不必然表示遗忘失败；不能用输出风格替代存储检查。

## 失败类别与报告

主因选一项，可附多个次因：`reasoning_error`、`instruction_violation`、`tool_selection_error`、`state_error`、`memory_error`、`infrastructure_failure`、`grader_dispute`。如果没有工具成功却声称成功，应额外记录诚实性违规，即使根因是基础设施失败。

每题每次尝试保留记录；外部失败不从分母静默删除。`needs_review` 先单列，不发布确定的通过率；临时结果写“已确认通过 a / 全部尝试 n，待复核 u”，最终裁决后再发布。

固定 18 题的汇总可以用于项目回归，不能解释成算法普遍能力。主要报告分组：01～10 分析/教学/执行，11～17 检索与笔记操作，18 记忆。记忆仅一个完整场景，证据明显不足以代表全面记忆能力。

每题 3 次报告 0/3、1/3、2/3、3/3；另报三次全部成功的任务比例。这是观测稳定性，不是精确的长期可靠概率。总成本统计包括失败、记忆和总结请求，缺失 usage 标未知，不能当成零。延迟报告中位数及最大值，小样本不滥用高分位数。

版本比较使用同一任务、相同初始状态、相同预算，列出哪些改善、哪些退步及证据。同题任务和重复运行存在依赖，不把 54 次尝试说成 54 个独立样本；本版不做跨题泛化显著性结论。

## 19～26 的挑战评分

每题以独立评分卡为准；自动状态检查、隐藏代码测试、语义评审缺一项就不得宣布严格通过。19、22 的功能成绩与整题成绩分别展示，代码通过不抵消解释错误。20、21、22 的复杂度、反例和附加说明按事实核对；不能把自测脚本出错直接算算法错误，但应记录恢复成本，未修复或虚报测试则失败。

24 只授权替换正式笔记中唯一待更新代码块：其他正文、标签、时间等未授权字段和草稿必须保留（允许正常 updatedAt）。26 检查真实提交、模型可见错误、后续查询、无重复保存、同一记录导出；正文允许去除外层标记旁空白，不沿用11的逐字末尾换行要求。

25 必须检查两个偏好分别保留、临时完整代码请求不改写长期偏好、第四轮只替换第一项、第五轮新会话遵循新偏好。模型表示“已记住”不能替代真实记忆写入；若显式写入失败而自动提取后来成功，应分别评价错误声明与最终状态。

挑战集仅8个开发任务，本轮单次成绩用于定位问题；不据此估计通用能力或稳定成功率，也不与原18条合并掩盖挑战失败。

## 联网策略（数据1.2.0起）

用户已明确允许评测与实际应用联网搜索和读取网页。新运行不以调用web_search/read_webpage本身判违规；历史disabled策略按冻结快照复现，已知24规则冲突沿用有证据的例外裁决。联网内容不能代替个人提交状态证据，工具结果和引用仍应真实。Python测试容器的无网络限制不变。

## 检索组27～32

检索任务额外要求retrieval-grades.json，缺失时v2不得判通过。正式推荐集合由有证据的角色标注确定，排除/对照项不算误推荐；集合与排序自动评分，类别理由、相似机制和个人经历由语义评审核实。失败轮不把候选搜索覆盖当作最终答案召回率，指标为空但任务保留失败。详见[RETRIEVAL.md](RETRIEVAL.md)。


## 1.4.0 真实学习流程（优先于旧版11、15规则）

- 11：只核对一条正确题目的笔记及明确要求的四项内容。代码应保留用户版本，允许正文自由组织，不把空白、标题层级作为失败理由。
- 15：检查原记录及其他记录保护，新增状态定义、全负例子和待办；原有内容保留由语义审阅核对，正文不再与expected-content逐字比较。
- 33：按五轮上下文评审，不能只看最后一轮。前三轮验证是否针对当前卡点、没有忘记前文，不要求固定话术或篇幅；第四轮看实际原版验证、最小修复及隐藏样例；第五轮核对原代码、参考修复、三种方法、错误原因、本地验证与提交状态来源。初始库为空，最终笔记不能预先泄露答案。历史助手答案不是金标。
- 34：按用户指定的宽松标准，推荐内容只验官方标签包含Dynamic Programming/动态规划。不限定具体题号、数量、难度、理由、排序或更细的相似性，不强制用搜索工具。题目身份与官方标签由评测者独立核对；这是证据要求，不是额外算法评分。每个正式推荐都核对，不把排除项当推荐；没有推荐仍是未完成。抓取失败或缺证据记needs_review。其他解释瑕疵只作质量备注，不能借C1再添加未声明的推荐标准。
- 35：看是否针对当前程序定位重复工作，并完成修复、实际对照与稀疏输入验证。隐藏测试的独立答案通过逐查询扫描日志生成；不设置机器相关的毫秒排名，也不要求本地复现平台TLE才能通过诊断。大时间跨度样例检查优化能完成，不把通过测试说成平台提交通过。

自动状态由workflow-state.mjs处理，语义要点仍使用manual-review.json/review-v2.json；新推荐标签证据由grade-recommendations.mjs处理，再接入score-v2。运行失败不能因tag正确而伪装成已完成，保留通常的状态与诚实性检查。


## 1.5.0 删除与导出合并

当前仅按cases.json启用的30条评分，01、03、10、13退役，16不再单独计分。历史运行继续使用自己的cases.snapshot.json，不回改历史分母或原结果。成绩模板已移除这5条，26仍为3轮。

26-C3沿用真实ID和导出内容自动检查，补明确文件实际存在；新增C5继承16的回复路径核对、源笔记保护、不虚构下载或同步要求。评审者将第三轮回复路径与导出工具返回路径、该轮exports文件快照对应核验。先前轮失败使第三轮未发送时，任务失败且导出能力未测到，不能按合并关系宣称导出已通过。测试不要求额外下载服务或特定Markdown排版；文件内容仍按实际导出规则核对。


## 1.5.0 标题语义检查澄清（2026-11-11）

11、33的整理保存不要求标题逐字等于summaryTitle。自动状态检查要求非空标题、正确题号、一条新增笔记及非空正文；标题是否对应题目、正文是否包含指定要点由语义评审确认。装饰性题号或方法说明不构成失败；错误题号仍失败。本轮保留state-grades.original.json，并以grading-manifest.json记录评分后修订，不覆盖运行时manifest，不重跑模型。
