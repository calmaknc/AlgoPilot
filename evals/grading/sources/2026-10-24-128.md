## 我的理解与需要澄清的点

先将数组转成集合，利用平均 O(1) 的成员查询寻找连续序列。如果每个元素都作为起点向后扫描，就会重复查找，最坏达到 O(n²)。因此需要筛选起点。

“选择尽量小的起点”更准确地说是：**只从每一段连续序列的最小值开始扫描**。不是只找整个集合的最小值，也不需要排序。

- 如果 `x - 1 in st`，说明 x 不是所在连续段的起点，直接跳过。
- 如果 `x - 1 not in st`，说明 x 是所在连续段的最小值，从这里向后扫描。
- 集合遍历顺序不影响结果：起点由前驱是否存在决定。

例如集合为 `{1, 2, 3, 4, 100, 200}`，只从 1、100、200 开始扫描。2、3、4 都因前驱存在而跳过。若不跳过，就会反复扫描 `1→2→3→4`、`2→3→4`、`3→4`、`4`。

## 抄写的参考答案

```python
class Solution:
    def longestConsecutive(self, nums: list[int]) -> int:
        st = set(nums)
        ans = 0

        for x in st:
            if x - 1 in st:
                continue
            y = x + 1
            while y in st:
                y += 1
            ans = max(ans, y - x)

        return ans
```

退出 while 时，y 是从 x 开始遇到的第一个不在集合里的整数，连续段是 `[x, y - 1]`，长度为 `y - x`。

## 为什么总时间是 O(n)

设原数组长度为 n，去重后有 m 个元素。

- 建立集合平均 O(n)。
- 外层循环检查 m 个元素，每个元素进行一次前驱查询。
- 每个连续段仅从起点展开一次，各段互不重叠，所有 while 成功查询总共不超过 m 次；每段还会有一次失败查询。
- 因此总时间平均 O(n)，额外空间 O(n)。不能仅因为有两层循环就直接相乘。

如果从每个元素展开，在长度为 m 的连续段上，累计扫描量为 `m + (m - 1) + … + 1`，达到 O(m²)。
