## 思路

排序后枚举第一个数 nums[k]，在右侧使用左右指针寻找两数之和为 -nums[k]。和偏小就右移 i，和偏大就左移 j。nums[k] > 0 时可以结束枚举；重复的 nums[k] 直接跳过。

## 我的原始代码

```python
class Solution:
    def threeSum(self, nums: list[int]) -> list[list[int]]:
        nums.sort()
        n = len(nums)
        
        ans = []
        for k in range(n - 2):
            if nums[k] > 0:
                break
            if k > 0 and nums[k] == nums[k - 1]:
                continue
            i, j = k + 1, n - 1
            while i < j:
                curr = nums[k] + nums[i] + nums[j]
                if curr < 0:
                    i += 1
                elif curr == 0:
                    ans.append([nums[k], nums[i], nums[j]])
                    break
                else:
                    j -= 1

        return ans
```

## 问题 1：找到一组解后不能直接 break

固定 k 时可能还有其他不同的数值配对。

反例：`[-4, -1, 0, 1, 3, 4]`。原程序输出 `[[-4, 0, 4], [-1, 0, 1]]`，漏掉 `[-4, 1, 3]`。k 指向 -4 时，找到 `(0, 4)` 后直接退出，没有继续找 `(1, 3)`。

## 问题 2：继续搜索时要跳过重复的左右值

如果只把 break 改成 `i += 1; j -= 1`，在 `[-2, 0, 0, 2, 2]` 上会输出两次 `[-2, 0, 2]`。外层对 k 去重并不能消除这种重复。

原版因找到一组就退出，暂时掩盖了内层重复输出的问题；修正提前退出后，需要同时补上内层去重。

## 为什么找到答案后可以同时移动两边

本人理解：只移动 i 会使和大于 0，只移动 j 则相反。

更准确地说，排序只保证非递减：只移动 i 时和大于或等于 0，只移动 j 时和小于或等于 0。等于 0 的情况来自重复值，对应同一个数值三元组。

找到 `a + b + c = 0` 后：固定 c，换成严格大于 b 的值，和必然大于 0；固定 b，换成严格小于 c 的值，和必然小于 0。因此使用当前 b 或 c 的新数值解都已排除，可以同时向内移动并跳过重复值，继续寻找其他组合。
