## 我的思路：相遇后，再走 a 步到入口

第一阶段用 [141 · 环形链表](2026-11-08-141.md) 的快慢指针判断是否有环。设：

- a：从头节点到环入口的步数，即非环部分的长度。
- c：环长。
- s：第一次相遇时，慢指针从头节点出发累计走的步数。

相遇时快指针累计走了 2s 步，两者同在环内的同一节点。它们进入环前都走过相同的 a 步，因此累计步数之差必为环长的正整数倍：

```text
2s - s = kc
所以 s = kc
慢指针入环后累计走的步数 = s - a = kc - a
```

**kc-a 是在环中累计走的步数，可以包含整圈**；相遇点在环中的位置由它对 c 取模决定。

第二阶段，把一个指针放回头节点，另一个留在相遇点，两者每轮都走一步：

- 从头出发的指针走 a 步，恰好到达入口。
- 从相遇点出发的指针再走 a 步，入环后累计走了 `(kc - a) + a = kc` 步，也恰好在入口。

在此之前，从头出发的指针还在环外，另一指针一直在环内，不可能提前相遇。若 a = 0，头节点就是入口，此时两个指针在第二阶段开始时已经相等，无须再走。

例如 a = 2、c = 3。第一次相遇时慢指针共走 3 步，即在环内走了 1 步。它从相遇点再走 2 步，就凑满一圈回到入口；从头出发的指针也恰好用这 2 步到入口。

## 我的代码

```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, x):
#         self.val = x
#         self.next = None

class Solution:
    def detectCycle(self, head: Optional[ListNode]) -> Optional[ListNode]:
        slow, fast = head, head
        while fast and fast.next:
            slow = slow.next
            fast = fast.next.next
            if slow is fast:
                while slow is not head:
                    slow = slow.next
                    head = head.next
                return slow
        return None
```

这里复用 head 作为第二阶段从头出发的指针；重新绑定局部变量不会改写链表的 next。两阶段都用 `is` 或 `is not` 比较节点身份。

- 时间 O(n)，额外空间 O(1)，不修改链表。
