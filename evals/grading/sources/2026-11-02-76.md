## 我的原始代码

```python
class Solution:
    def minWindow(self, s: str, t: str) -> str:
        t_count = Counter(t)
        curr_window = {}
        left = 0
        while not s[left] in t_count:
            left += 1
        right = left
        res = None
        res_len = float('inf')

        def check(src, tgt):
            for key, value in tgt.items():
                if src.get(key, 0) < value:
                    return False

            return True

        while right < len(s):
            curr_window[s[right]] = curr_window.get(s[right], 0) + 1
            if check(curr_window, t_count):
                res_len = min(res_len, right - left + 1)
                res = (left, right)
                curr_window[s[left]] -= 1
                left += 1
                while left <= right and not s[left] in t_count:
                    left += 1
                curr_window[s[left]] += 1
            right += 1

        return s[res[0]: res[1] + 1] if res else ""
```

独立运行需导入 `from collections import Counter`。

## 问题一：初始化寻找目标字符时可能越界

```python
while not s[left] in t_count:
    left += 1
```

没有检查 left 是否仍在 s 内。例如 `s = "abc"`、`t = "z"`，原程序本地运行触发 IndexError。

这段预扫描不必保留：直接从 left = 0 开始遍历，非目标字符可以在后续缩窗时正常移出。参考修正版另对空输入提前返回。

## 问题二：满足条件后只缩一次，可能漏掉更短答案

原程序使用 `if check(...)`，只尝试删除一次左端字符；应使用 `while check(...)`，直到窗口不再覆盖 t。

反例：`s = "aab"`、`t = "ab"`。原版本地返回 aab，正确答案为 ab。

```text
右端到达 b，当前窗口 aab 覆盖 ab。
记录 aab，长度 3。
移出第一个 a，窗口变为 ab，仍然覆盖目标。
应继续记录 ab，长度 2，再尝试缩窗。
再移出 a 后，只剩 b，不再覆盖，停止缩窗。
```

### 为什么是 while：固定右端，寻找尽可能靠右的合法左端

目标是最短覆盖子串。覆盖条件刚满足，只说明找到了一个合法窗口，并不说明它已经最短：左端可能还有多余的目标字符或非目标字符。

固定 right，不断右移 left：窗口只会变短，字符计数只会减少。只要仍然覆盖 t，每个新窗口都比上一个更短，需要记录并继续尝试。第一次不再覆盖时，继续删除只会让字符更少，不可能重新满足条件，所以停止缩窗，等待右端加入新字符。

这建立了覆盖条件对缩窗的单调性：**删除字符可能使合法变为不合法，却不会让不合法重新变合法。** 注意它与 560 题含负数区间和的情况不同。

已经处理并放弃的更早左端也不必退回：它曾与某个更早的右端形成合法窗口并被记录；以后沿用这个左端、配更晚右端只会更长，不可能改善之前的答案。因此 left 可以始终向右移动。

整体流程：

```text
右端加入一个字符
    ↓
只要当前窗口覆盖 t：
    若更短，更新答案
    移出左端字符，left 右移
    再检查能否继续缩小
    ↓
不再覆盖时，扩展下一步右端
```

## 问题三：左边界移动与计数不一致，并可能再次越界

```python
curr_window[s[left]] += 1
```

不应执行：移动后新的左端字符原本就在窗口中，没有新加入，再加 1 会凭空增加计数。

而下面的跳过逻辑只移动指针，没有减少被移出字符的计数：

```python
while left <= right and not s[left] in t_count:
    left += 1
```

非目标字符不参与 check，因此其陈旧计数本身不一定改变覆盖判断，但仍然破坏了“计数准确对应窗口”的性质，也使实现更难核对。无需特殊跳过，逐个移出即可，总计依然是线性次数的左移。

统一操作应为：

```python
curr_window[s[left]] -= 1
left += 1
```

每加入一个右端字符就加 1，每移出一个左端字符就减 1，确保 curr_window 准确表示当前窗口。零计数的键可以留在字典中，不影响 check。

此外，原版先增加 left 后再访问 `s[left]`，也可能越界：`s = "a"`、`t = "a"` 的原程序本地触发 IndexError。

## 问题四：最短长度与答案位置必须同步更新

```python
res_len = min(res_len, right - left + 1)
res = (left, right)
```

res_len 虽然保留历史最短值，但 res 无条件被新位置覆盖，即使新窗口更长也一样，造成两者含义不一致。

只有发现更短合法窗口时，才同时更新：

```python
length = right - left + 1
if length < res_len:
    res_len = length
    res = (left, right)
```

## 保留原结构的修正版

以下为助手此前给出的参考实现。本人反馈理解后修改并提交通过，未另提供最终提交源码，因此不将其作为本人完整提交源码的逐字记录。

```python
from collections import Counter

class Solution:
    def minWindow(self, s: str, t: str) -> str:
        if not s or not t:
            return ""

        t_count = Counter(t)
        curr_window = {}
        left = 0
        res = None
        res_len = float('inf')

        def check(src, tgt):
            for key, value in tgt.items():
                if src.get(key, 0) < value:
                    return False
            return True

        for right, ch in enumerate(s):
            curr_window[ch] = curr_window.get(ch, 0) + 1

            while check(curr_window, t_count):
                length = right - left + 1
                if length < res_len:
                    res_len = length
                    res = (left, right)

                curr_window[s[left]] -= 1
                left += 1

        return s[res[0]:res[1] + 1] if res else ""
```

check 检查每种目标字符的数量是否足够，不是只检查字符是否出现。例如 t = AAB，窗口必须至少含两个 A 和一个 B。允许多余字符，只要各项计数均不小于要求即可。

## 复杂度与验证边界

- 设 n = len(s)，m = len(t)，d 为 t 的不同字符数。
- 左右边界各自最多移动 n 次，check 的调用总数为 O(n)。每次 check 最坏遍历 d 项，所以总时间上界 O(m + n*d)，不能只看指针移动就直接称本实现为一般意义上的 O(n+m)。
- 计数字典空间为 s 与 t 中不同字符数的量级，最坏 O(n+m)；返回子串的复制空间另计。
- 后续可维护已满足要求的字符种类数，将每次覆盖判断改为 O(1)，从而达到平均 O(n+m) 时间；此记录保留当前 check 版，不冒充已实现该优化。
- 上一轮本地复现：原版在 abc/z、a/a 上越界；aab/ab 返回 aab；经典例 ADOBECODEBANC/ABC 碰巧返回正确的 BANC，并不能说明原版无误。
- 上一轮参考修正版：s 从 abx 中取字符、长度 0～5，t 从 ab 中取字符、长度 1～3，共 5,096 组输入与暴力最短覆盖结果对照通过。

## 一句话复习

**右端扩展直到覆盖目标，覆盖后不断收缩左端寻找更短解，直到失去覆盖；计数跟随边界变化，答案只在变短时更新。**
