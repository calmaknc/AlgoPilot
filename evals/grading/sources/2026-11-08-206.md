## 我的原始代码

```python
class Solution:
    def reverseList(self, head: ListNode | None) -> ListNode | None:
        curr, nxt = head, head.next
        while nxt != None:
            tmp = nxt.next
            nxt.next = curr
            curr, nxt = nxt, tmp
        return curr
```

## Bug：旧头成了新尾，却仍指向原来的第二个节点

以 `1 → 2 → None` 为例。执行 `nxt.next = curr` 后，节点 2 指向节点 1，但 `1.next` 仍然指向节点 2。函数返回节点 2 后，沿 next 遍历会得到：

```text
2 → 1 → 2 → 1 → …
```

**反转循环本身仍会结束**：每轮在改写指针前用 tmp 保存了原后继，nxt 会沿原链表前进到 None。问题出在返回结果：评测如果沿 next 遍历并收集输出，就一直遇不到 None，输出缓存可能持续增长，最终报内存超限。本地验证了成环，未复现或确认评测器内部的内存行为。

空链表也是一个独立边界：head 为 None 时直接访问 `head.next` 会报错，需要提前返回。

## 为什么要先保存 head.next，再断开

`head.next` 是从旧头进入剩余待反转链表的入口。修改 next 会覆盖这条连接，所以必须先用 nxt 保存第二个节点的引用：

```python
curr, nxt = head, head.next
curr.next = None
```

这样断开后，curr 指向已反转部分的头（此时只有旧头一个节点），nxt 仍指向待处理部分的头。旧头的 next 成为 None，之后它始终是反转结果的尾节点。

如果反过来，先写 `head.next = None`，再执行 `nxt = head.next`，nxt 读到的已经是 None，循环不会开始，结果只剩旧头，原来的后续节点没有被接进结果。

循环内的 `tmp = nxt.next` 同理：**每次改写某个节点的 next 前，先保存原来的后继，才能在反转指针后继续沿原方向处理剩余节点。**

## 最小修正版

以下为助手此前给出的参考代码，与本人反馈的提交通过状态分开记录：

```python
class Solution:
    def reverseList(self, head: ListNode | None) -> ListNode | None:
        if head is None:
            return None

        curr, nxt = head, head.next
        curr.next = None

        while nxt is not None:
            tmp = nxt.next
            nxt.next = curr
            curr, nxt = nxt, tmp

        return curr
```

每轮把 nxt 接到已反转部分的前面，再用 tmp 进入尚未处理的部分。nxt 到达 None 时，curr 就是新头。

- 时间 O(n)，额外空间 O(1)，原地修改 next 指针。
- 上一轮本地对两节点例子做了有限步遍历：原版输出 `2 → 1 → 2 → 1 → …`，修正版输出 `2 → 1 → None`；修正版也检查了空链表返回 None。本次整理未重复运行。
