若对每个长度为 k 的窗口重新扫描求最大值，每个窗口需要 O(k)，共有 n-k+1 个窗口，总时间 O((n-k+1)k)，通常写为 O(nk) 上界。相邻窗口大部分元素相同，重复扫描造成浪费。

只记当前最大值也不够：它离开窗口后，还需要知道剩余元素中谁最大。因此需要保存一组仍可能成为最大值的候选。

## 我的单调队列代码

```python
class Solution:
    def maxSlidingWindow(self, nums: List[int], k: int) -> List[int]:
        dq = deque()
        for i in range(k):
            while dq and nums[dq[-1]] < nums[i]:
                dq.pop()
            dq.append(i)

        ans = [nums[dq[0]]]
        j = k
        while j < len(nums):
            while dq and nums[dq[-1]] < nums[j]:
                dq.pop()
            dq.append(j)

            while dq and dq[0] < j - k + 1:
                dq.popleft()
            ans.append(nums[dq[0]])
            j += 1

        return ans
```

独立运行需要 `from collections import deque` 和 `from typing import List`。代码按题目条件 `1 <= k <= len(nums)` 使用。

## 核心原因：更大且更晚的元素，可以永久淘汰更小且更早的元素

设旧下标 a < 新下标 b，且 nums[a] < nums[b]。

从 b 加入开始，只要未来某个窗口还包含 a，就一定也包含 b：窗口右端已经到达 b，左端既然还没越过 a，就更没越过 b。而 b 的值更大，所以 a 不可能成为这个窗口的最大值。等 b 离开窗口时，a 更早就已离开，不会重新获得机会。

因此 a 同时具有两个劣势：

1. 值更小，无法胜过 b。
2. 位置更早，会比 b 更早过期。

**它在当前及未来的窗口里，都不再需要作为最大值候选，可以永久删除。** 这正是队尾 while 弹出的依据，而不只是为了把最大值放到队首。

例如候选值依次为 `[5, 1]`，新来一个 3：

```text
1 比 3 小，而且比 3 更早过期，所以删除 1。
5 比 3 大，不能删除 5。
保留候选 [5, 3]。
```

为什么还要保留 3？虽然现在它不如 5，但 5 会先离开窗口，3 可能随后成为最大值。因此不能只留下当前最大值。

## 队列维护的两个顺序

每次清理完毕后：

- 下标从队首到队尾递增：旧元素在前、新元素在后。
- 对应数值从队首到队尾单调不增：最大值候选在最前面。

新元素从队尾加入，先连续淘汰队尾比它小的元素，再接到剩余候选后面，数值顺序自然保持单调不增。队列保存的是候选，不必保留窗口内所有元素，也不对原数组排序。

有些小元素不能立刻删除，因为此时尚未出现一个更大且更新的替代者；它们可以保留在队尾等待后续机会。

### 为什么代码用 <，不是 <=

这份代码只弹出严格小于新值的元素，所以会保留等值，准确地说是“单调不增”，不一定严格递减。例如 `[3, 3]` 的两个下标都可以留在队列里，旧的过期后使用新的。

也可以改用 `<=`，淘汰更早的等值元素：新元素一样大且更晚过期，足以替代它。两种写法都正确；使用 `<=` 时对应数值严格递减。

## 为什么需要双端队列，为什么保存下标

队列两端承担不同的删除任务：

| 操作位置 | 删除原因 | 代码 |
| --- | --- | --- |
| 队尾 | 被新来的更大元素淘汰，失去竞争力 | `dq.pop()` |
| 队首 | 已离开当前窗口，失去有效性 | `dq.popleft()` |

两种删除都需要高效完成，因此使用 deque。普通列表从头部删除会移动后面的元素，不能保持同样的复杂度保证。

保存下标可以同时获取数值 `nums[dq[-1]]`，以及判断元素是否过期。右端为 j 时，当前窗口是闭区间 `[j-k+1, j]`，所以：

```python
dq[0] < j - k + 1
```

意味着队首在窗口左边，必须删除。恰好等于左边界时仍在窗口内，不能删除。

由于下标递增，过期元素只能出现在队首一侧；删除它们后，队列里剩下的都是有效候选，且队首值最大。因此答案就是 `nums[dq[0]]`。

原代码先从队尾淘汰、加入新元素，再从队首清理过期元素，也是正确的；关键是在读取最大值之前完成清理。连续滑动一格时，若上轮已清理干净，本轮最多新增一个过期下标，队首清理写 while 则更稳妥直观。

## 为什么总时间是 O(n)

虽然代码存在 while，但每个下标只会：

- 从队尾进入一次。
- 最多离开一次：要么被队尾淘汰，要么从队首过期删除。

所有入队、出队操作加起来为 O(n)，不是每个窗口都重新做 O(k) 工作。

- 时间 O(n)。
- 队列额外空间 O(k)，最坏如窗口数值递减，所有元素都需保留；排除过期元素前可能短暂多一个下标，不影响空间量级。
- 输出空间 O(n-k+1)，与队列辅助空间分开计算。
