## 最初思路：双指针为什么不可行

本人最初考虑：左右指针都从 0 开始，和偏小就扩展右边界，和等于 k 就答案加 1，和偏大就缩小窗口，并用前缀和快速求区间和。原描述中的“i 向左移动”按缩窗意图应理解为左边界 i 向右移动。

这种根据区间和大小决定移动方向的方法，依赖单调性：如果元素全为正数，扩展右边界使和增大，移出左端元素使和减小。但本题允许负数：扩展窗口可能使和减小，缩窗也可能使和增大，不能依据当前和的大小安全排除候选。

反例：`nums = [3, -1]`，`k = 2`。读到 3 时和偏大，如果立即移走它，就会漏掉随后整个合法子数组 `[3, -1]`。

此外，本题要统计所有非空连续子数组。即使没有负数，若允许零，同一个右端点也可能有多个合法起点：`[0, 0]`、k = 0 的答案为 3，对应两个单元素子数组和整个数组，不能简单地每轮相等只加 1。

**前缀和能加快求和，但不能创造指针移动所需的单调性。** 这并不是说双指针只能处理正数，而是这里“和大就缩、和小就扩”的移动依据不成立。

## 从前缀和推导哈希计数

定义 `pre[t]` 为前 t 个元素的和，`pre[0] = 0`。非空子数组 `[l, r]` 的和为：

```text
pre[r + 1] - pre[l] = k
因此 pre[l] = pre[r + 1] - k
```

遍历到当前元素时，prefix_sum 就是 `pre[r + 1]`。只需知道：**此前有多少个前缀和等于 prefix_sum - k？** 每个满足条件的旧前缀都对应一个不同的合法起点，将其出现次数累加即可。

不必保存整个前缀和数组；维护当前前缀和，以及此前各前缀和的出现次数。

## 我的原始代码

```python
class Solution:
    def subarraySum(self, nums: List[int], k: int) -> int:
        # 暴力做法是枚举子串的idx：i，j，但这样是平方
        n = len(nums)
        prefix_sum_record = {0: 1}
        prefix_sum = 0
        ans = 0

        for i in range(n):
            prefix_sum += nums[i]
            if prefix_sum - k in prefix_sum_record:
                ans += prefix_sum_record[prefix_sum - k]
            if prefix_sum in prefix_sum_record:
                prefix_sum_record[prefix_sum] += 1
            else:
                prefix_sum_record[prefix_sum] = 1
        return ans
```

原版逻辑正确。独立运行时，List 注解需 `from typing import List`；简化版使用内置的 `list[int]`。题目讨论的是连续子数组，原注释中的“子串”在这里应称为“子数组”。

## 为什么初始化为 {0: 1}

**表示还没有读取任何元素时，和为 0 的空前缀已经出现一次。** 它对应 `pre[0] = 0`，是数组开始之前的前缀边界，不是一个真实的数组元素，也不是说答案中要计入空子数组。

空前缀让“从下标 0 开始的子数组”也能用统一公式统计。

例如 `nums = [3]`、k = 3：

```text
读入 3，当前 prefix_sum = 3
需要查询旧前缀和 3 - 3 = 0
字典中有一次 0，因此找到一个答案：[3]
```

如果初始化为空字典，这个从开头开始的子数组就会漏掉。对于 `[0]`、k = 0，预存的空前缀与当前前缀配对，得到的是包含一个元素的 `[0]`，不是空子数组。

## 为什么必须先查询，再记录当前前缀和

在查询阶段，字典只应包含**当前前缀之前**的前缀：处理下标 r 时，包含 `pre[0]` 到 `pre[r]`，不包含当前的 `pre[r + 1]`。

这样选出的左端边界一定满足 `l <= r`，子数组长度至少为 1。查询后，再把当前前缀记录进去，供后续位置使用。

如果先记录当前前缀，那么当 k = 0 时，当前前缀会与自身配对：

```text
pre[r + 1] - pre[r + 1] = 0
```

这对应长度为 0 的空区间，会错误地增加答案。

### 最短反例：[0]，k = 0

正确顺序：

```text
初始化 counts = {0: 1}
读入 0，prefix_sum = 0
先查询 counts[0] = 1，ans 增加 1
再记录当前前缀，counts 变为 {0: 2}
最终答案为 1
```

错误顺序：

```text
初始化 counts = {0: 1}
读入 0，prefix_sum = 0
先记录，counts 变为 {0: 2}
再查询，ans 增加 2
多出来的一次就是当前前缀与自身配对的空区间
```

因此，**预存空前缀用于统计从开头开始的非空子数组；不提前记录当前前缀用于避免统计空子数组**，两者并不矛盾。

## 为什么记录次数，不能只用集合

同一个前缀和值可以对应多个不同位置，每个位置都代表一个不同的起点边界。

例如 `[0, 0]`、k = 0：

| 当前元素下标 | 当前前缀和 | 查询前旧的 0 前缀数 | 本轮新增答案 | 查询后记录的 0 前缀数 |
| --- | --- | --- | --- | --- |
| 0 | 0 | 1 | 1 | 2 |
| 1 | 0 | 2 | 2 | 3 |

答案为 1 + 2 = 3。集合只能知道 0 出现过，无法知道它此前出现了几次，会漏计。

## 简化参考代码

以下为助手此前给出的参考实现；未收到本人采用此版本或提交的反馈：

```python
class Solution:
    def subarraySum(self, nums: list[int], k: int) -> int:
        counts = {0: 1}
        prefix_sum = ans = 0

        for num in nums:
            prefix_sum += num
            ans += counts.get(prefix_sum - k, 0)
            counts[prefix_sum] = counts.get(prefix_sum, 0) + 1

        return ans
```

直接遍历元素，省去 n 与下标；`dict.get(key, 0)` 在键不存在时返回 0，合并原版的存在性判断与分支。算法本身没有改变。

## 复杂度与验证边界

- 平均时间 O(n)，每个元素进行常数次哈希查询与更新，时间量级已最优。
- 额外空间 O(n)，最坏保存 n+1 个不同的前缀和。

## 一句话复习

**当前前缀和减去目标值，得到要查找的旧前缀和；先累计旧前缀的出现次数，再把当前前缀记录进去。**
