## 我的总结与澄清

本人总结：检查 nums[i] 是否等于 i+1，不在位置上就交换，超出范围则跳过；归位后找到第一个 nums[i] != i+1 的位置，答案为 i+1，如果全在位则为 n+1。

需要澄清“把 nums[i] 交换到 i+1 的位置”：**数值 x = nums[i] 应放到下标 x-1，而下标 i 的理想数值是 i+1。** 这两个方向不能混淆。例如当前值是 3，就应把它送到下标 2，与当前位置 i 无关。

## 为什么只处理 1～n

长度为 n 的数组，缺失的最小正数一定在 `[1, n+1]` 内：如果 1～n 全出现，答案为 n+1；否则答案就是其中最小的缺失值。

因此只需利用 n 个位置，给数值 1～n 各分配一个位置：`x → 下标 x-1`。非正数和大于 n 的数都无需归位，但可能在其他数归位时被动交换，不必主动删除。

数组本身充当哈希表，不另外分配集合。

## 我的代码

```python
class Solution:
    def firstMissingPositive(self, nums: list[int]) -> int:
        n = len(nums)
        for i in range(n):
            while 1 <= nums[i] <= n and nums[nums[i] - 1] != nums[i]:
                j = nums[i] - 1
                nums[i], nums[j] = nums[j], nums[i]

        for i in range(n):
            if nums[i] != i + 1:
                return i + 1

        return n + 1
```

## 为什么用 while，为什么检查目标位置

交换后，当前位置可能换进来另一个仍需要归位的数，必须继续检查，不能只交换一次。

例如 `[3, 4, -1, 1]`：

```text
i = 0：把 3 送到下标 2，得到 [-1, 4, 3, 1]。
       当前值 -1 超出有效范围，停止。
i = 1：把 4 送到下标 3，得到 [-1, 1, 3, 4]。
       换进来的 1 仍需归位，继续送到下标 0，得到 [1, -1, 3, 4]。
最后扫描：下标 1 不等于 2，因此答案为 2。
```

条件 `nums[nums[i] - 1] != nums[i]` 表示：**目标位置尚未放好同样的值，才需要交换。**

- 当前值已经归位时，条件不成立，停止。
- 当前值重复，且目标位置已有相同值时，也停止；否则会反复交换两个相同值，陷入死循环。例如 `[1, 1]` 的第二个 1 不应再与第一个 1 交换。
- 范围判断必须先执行，确定目标下标有效，再访问目标位置；Python 的 and 短路求值保证了这一点。

## 为什么扫描第一个不在位的位置就够了

归位阶段结束后，每个出现过的有效数值 x 都有一个副本在下标 x-1。若该位置没有 x，就说明 x 没出现。

从左往右扫描，第一个 `nums[i] != i+1` 就是最小缺失正数；若全匹配，则 1～n 均存在，返回 n+1。

这不是要把所有原始元素排好序；无效值与多余副本无需安排位置。

## 复杂度与验证边界

- 时间 O(n)：每次成功交换都把一个有效数值放到正确位置；已经归位的值不会再被交换走，因为目标位置已有同值时会停止。归位位置的数量最多 n 个，所以所有 while 的成功交换总次数为 O(n)，不是两层循环相乘。
- 额外空间 O(1)，会原地改变 nums。
