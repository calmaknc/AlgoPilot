# 检索组（27～32，数据1.3.0）

原26条保持不变。新增6条、8轮，使用32篇真实Hot100笔记的完整快照初始化临时SQLite；不是只放正确答案。每题空记忆、独立数据库，题内多轮共享会话状态。允许联网，但公开资料不能证明个人做题经历。

| 编号 | 场景 | 主要检验 |
| --- | --- | --- |
| 27 | 找全双指针类别笔记 | 相向、快慢、固定间距与归并；滑动窗口分开，排除560中被否定的方法 |
| 28 | 找滑动窗口题 | 固定/可变长度分类，排除仅“连续子数组”或推荐链接匹配 |
| 29 | 找一步/两步的链表技巧 | 判环、入口、中点；区分固定间距删除与普通指针改链接 |
| 30 | 最大连续和→统计指定和 | 相似题随目标变化；推荐练习不冒充完成记录 |
| 31 | k组翻转链表 | 同题+两个基础题的相似排序；通过反馈与最终源码归属 |
| 32 | LRU机制无直接记录 | 检索无结果的边界；基础哈希技巧不等于做过该题 |

所有源正文不改写，题号从文件名、标题从首行、标签从分类行提取；标签不刻意标准化。例如“相向双指针”和“双指针（快慢指针）”原样保留。32篇构成明确的本次可检索语料范围，不代表用户全部历史；无结果不能推断用户从未做过。

## 执行和评分

```sh
node --env-file=.env evals/run-live.mjs --group retrieval
node evals/grade-state.mjs <运行目录>
node evals/grade-hidden.mjs <运行目录>
# 根据实际答案标注retrieval-review.json，再执行检索集合评分
node evals/grade-retrieval.mjs <运行目录>
# 逐项语义评审形成manual-review.json与review-v2.json
node evals/summarize.mjs <运行目录>
node evals/score-v2.mjs <运行目录>
```

这些任务没有算法隐藏样例，仍生成空hidden-grades以兼容统一流程。

`cases.json`的retrieval字段给出逐轮必需命中、允许额外命中、对照项、必要排序和读取要求。它只留在评分侧。提示不会提供正确题号集合或总笔记数。

`retrieval-review.json`每项为 `{id, turns:[{turn, selectedIds, evidence, rationale}]}`：评测者根据最终回答标注正式推荐的ID及顺序，不把否定/对照列表中的ID混进去。需要自然语言审阅，不是假装全自动。若有未预料但合理的相似候选，先核对语料和任务要求，再记录金标争议，不能机械判错。

自动评分计算必需结果召回率、推荐精确率、漏检/误推荐/不存在ID、推荐是否有实际全文读取、首选是否正确。常规多轮允许沿用前轮已读证据；30第二轮明确要求重新读取，按本轮检查。无直接记录的32至少要有成功检索；是否搜索充分、措辞是否诚实仍需语义评审。没有人工标注时为needs_review，不计通过。

评分2.0合并时新增检索证据检查：缺失或待复核不可通过；集合检查失败会反映到核心结果。笔记不变由grade-state自动检查，分类理由、相似机制、个人完成证据由逐项语义评审判断。质量问题与核心任务仍分开报告。

精确率/召回率依赖已审阅的相关性金标；这是小规模开发集，不据此宣称全库搜索的通用能力或稳定成功率。
